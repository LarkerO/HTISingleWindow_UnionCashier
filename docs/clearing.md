# 清算业务规则

## 订单状态

| 订单类型 | 平台记录的主要状态 | 完成条件 |
| --- | --- | --- |
| 普通付款 | `pending → processing → paid` | 已实际扣款并计入商户余额 |
| 预授权 | `pending → processing → held → paid / released` | `held` 为已冻结，`paid` 为已结算，`released` 为全额解除 |
| 免密签约 | `pending → active → revoked` | 玩家确认后可扣款。玩家或商户解约后禁止新扣款 |
| 免密扣款 | 独立的支付订单 | 用扣款订单查询及退款 |
| 资金失败 | `failed`，或暂时保留 `processing` | 确定失败时可查看失败原因，结果不确定时进入人工复核 |

待确认收银台和签约链接有效期为 30 分钟。玩家回跳后，交易结果以验签查询为准。解约前已受理的扣款继续处理。

## 支付与清算

- 游戏金额使用整数，Vault 和计分板分别记账。纯游戏支付每笔由选中的一种方式承担。预付卡允许补差额时先冻结卡内金额，其余从所选游戏钱包扣除。
- 预授权在确认时扣入托管。实际结算金额可为 0 到已冻结金额，差额按原来源退回。退款同样退至原来源，组合支付按后使用的资金来源优先退还。
- 正式收款按入账时的商户清算周期计算可提现时间。D+0 即时。T+0 工作日即时，周末顺延。T+1 和 T+2 在该工作日基础上加一或两个工作日。以北京时间周一至周五统一计算。
- 分账和提现仅可使用已到清算期的对应钱包余额。提现指定玩家时转至该玩家的同种游戏钱包，未指定时转给超级管理员。
- 独立的请求编号贯穿异步队列和插件持久化流水。后端重投相同指令时，游戏端返回已有回执。游戏钱包和 SQL 之间存在执行结果不确定时，由超级管理员核对后处理。

## 游戏钱包身份

- 自动绑定只使用 Portal 主展示账号。主账号绑定 UUID 为空时采用 Portal 解析的同名游戏 UUID；次要账号不参与回退。
- 超级管理员可手工绑定 UUID 并保留变更记录，手工结果优先于重新登录的自动同步，可恢复为最近获取的 Portal 主账号。
- UUID 变化会清除余额缓存、更新唯一归属索引。已受理订单继续使用原 UUID；退款和预授权释放退回原资金来源，不随新绑定转移。免密协议的 UUID 与当前钱包不一致时禁止新扣款，需要重新签约。

## 预付卡

平台卡支持商户名单，商户专用卡只能在发行商户使用。可为每一类卡设置适用场景、单笔限额、组合支付、折扣、转让费、退卡比率和退卡费。未激活卡使用卡号和卡密领取，激活后卡密失效。

- 购卡保存面值、折扣、转让和退卡条款。商户名单、支付场景、限额与组合规则采用当前卡种设置。
- 卡按买卡时的游戏钱包来源结算。若有折扣，差额从发行方该钱包的可用余额中预留。平台管理员可单独充值补贴金。
- 冻结中的卡不可转让或退卡。卡片转让后，随后的原卡退款进入接收方持有的卡。
- 退卡金额为剩余面值折算的实付金额，乘退款比率再扣退卡手续费。金额按整数计算，最低为零。0% 退卡政策关闭卡但退款为零。
- 玩家可查激活、冻结、支付、释放、转让、退款等个人记录。平台和商户发行方可查各自发行卡的记录。

## 限额与核对

- 玩家限额按支付方式，包含单笔实际承担金额及月度笔数。
- 商户限额包含单笔、月累计金额与月度笔数。有效待付款订单会占用额度。月度按北京时间计算，已付款后的退款保留原交易的收款统计。
- 沙箱和正式环境分别计数。沙箱使用模拟游戏余额，入账立即可提现至模拟钱包。
- 对账流水包含付款正数和退款负数。升级前的退款只能使用旧订单上的累计数，历史退款按原订单时间展示。玩家按本人和所选商户查询，商户按自身权限查询。
